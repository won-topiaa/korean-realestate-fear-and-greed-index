# 서울 아파트 공포탐욕지수

주식시장의 공포탐욕지수(CNN Fear & Greed Index)를 서울 아파트 시장에 옮긴 지수예요. 시장 심리를 0~100으로 나타내고(0 극단적 공포, 50 중립, 100 극단적 탐욕), 서울 전체·5대 권역·25개 구로 나눠 볼 수 있어요. 2026년 10월에 수도권(경기·인천)과 광역시(부산·대구·광주·대전·울산) 7곳으로 넓혔고, 7곳 모두 미리 정한 공개 기준을 넘어 공개했어요([아래](#수도권광역시-확장-2026-10-20)).

## 사이트 기능

### 지도 (`/`)
- 첫 화면: 지수가 무엇인지 한 줄 정의, '지금 서울 점수 · 구간'과 0~100 다섯 구간 막대, 지난달 대비.
- 월 슬라이더(2006년~), CNN식 반원 게이지(서울·5대 권역), 지도(5대 권역 / 25개 구), 지도 옆 지수 추이, 지역별 구성·순위·서울 안 상대 강도.

### 단지 검색 (`/apt/`)
단지 이름이나 동(초성도 가능)으로 찾으면, 그 단지 평형별로 **가장 최근 실거래가가 최근 거래들 사이에서 어디쯤인지** 0~100으로 보여줘요. 주식 스토캐스틱(%K)과 같은 식이에요.

- **점수** = (최근 거래 보정가 − 비교 거래 최저) ÷ (최고 − 최저) × 100
- **비교 거래**: 같은 단지·같은 평형의 최근 10건(2년 안). 같은 평형이 5건 미만이면 같은 단지 다른 평형 거래를 환산해 10건까지 채워요. 5건이 안 되면 점수를 내지 않아요.
- **보정가**: 층(8~10층 기준), 그사이 구 시세 변화(구별 실거래 반복매매지수), 평형 차이를 맞춘 가격. 해제·직거래는 빼요.
- **설계 근거** (`apt_study.py`, 2006~2026 실거래 141만 건):

| 항목 | 결과 |
|---|---|
| 기간 | 1개월은 같은 평형 5건 이상인 단지가 0.2%뿐. 고정 기간 대신 '최근 10건(최대 2년)'이 범위와 정확도 모두 좋았음 |
| 층 보정 | 1층 −9.0%, 2층 −5.3%, 3층 −3.4%, 4층 −2.5%, 5층 −1.7%, 6~7층 −0.7%, 8~10층 기준, 11~29층 +0.3~0.8%, 30층 이상 +3.1% (2006~15년과 2016~26년이 거의 같음). 넣으니 같은 평형 다음 거래와의 순위상관이 0.41 → 0.50 |
| 평형 환산 | 단지별 평형 비율(최근 3년)로 환산하면 2021년~ 거래 가격 오차 중앙값 4.6% (㎡당 같은 값 14.3%, 서울 공통 비율 8.8%, 같은 평형끼리 3.3%) |
| 다른 평형으로 채우기 | 같은 평형 5건 미만일 때만 채우면 정확도는 그대로(0.48)이고, 지금 점수가 나오는 단지·평형이 73% → 88%. 평형을 무조건 섞으면 오히려 나빠짐(0.44) |
| 의미 | 2014~2026년 82만 건: 80점 이상 뒤 같은 평형 거래는 평균 2.0% 낮았고, 20점 이하 뒤에는 4.6% 높았음(시장 변화를 뺀 값) |

- 지금(2026-10-14 신고분): 9,271개 단지, 최근 2년 거래가 있는 평형 14,896개 중 10,641개에 점수.

  - 지번으로 못 찾은 단지(새 단지는 대장 지번이 다른 경우가 많아요)는 그 동네 대장 전체에서 단지 이름으로 다시 찾아요(`python bldg_fetch.py fill`). 이름으로도 없으면 90일 뒤 다시 찾아요.
  - 법정동 코드가 없는 동은 건축물대장에 동 코드를 하나씩 물어 만든 코드표(`data/molit/bjdong.csv`)를 써요.
  - 실거래에선 여러 단지로 나뉘었지만 대장은 한 장부인 경우(예: 마포래미안푸르지오 1~4단지)는 화면에 합친 기준이라고 알려요.
  - 오래된 단지(구대장)는 대장에 대지면적·용적률·건폐율·주차가 0으로 비어 있어요(약 8%). 대지면적은 대장의 대표 지번 + 부속지번의 **토지대장 면적**(브이월드 토지임야목록)을 더해 채우고, 용적률 = 용적률 산정 연면적 ÷ 대지, 건폐율 = 건축면적 ÷ 대지로 계산해요(`python bldg_fetch.py land`, 브이월드 키 `VWORLD_KEY`는 로컬 `.env`에만). 대지면적이 있는 단지 80곳으로 시험했을 때 79곳이 ±5% 안이었어요(대표 지번만 쓰면 84%). 건축물대장 하루 호출 한도에 걸리면 건물 면적을 층별개요 합(지상층 합 ≈ 용적률 산정 연면적, 1층 합 ≈ 건축면적)으로 어림하고, 다음 실행에 대장 값으로 다시 계산해요(은마 203% → 204%). 용적률 60% 미만·1,000% 초과, 건폐율 90% 초과는 지번 짝이 일부만 맞은 것으로 보고 비워요.
- 2026-10-16 기준 8,907개 단지(96%) 정보를 찾았고, 용적률이 빈 단지는 22곳이에요. 정보가 틀렸으면 단지 화면의 '알려 주기'로 메일을 보낼 수 있어요.
- 단지 자료(`results_apt/`)는 저장소에 올리지 않고 배포 때마다 저장소의 실거래 자료로 다시 계산해요(1분 안쪽).

### 신고가 단지 (`/highs/`)

### 모의 투자 (`/sim/`)
- `sim_build.py`: '그때 샀다면 지금 얼마?' 단지·평형별 분기 가격(8~10층 기준 실거래 중앙값)으로 산 시기·판 시기를 골라 수익률을 계산하고, 같은 기간 구·서울 실거래지수와 예금을 함께 보여줘요. 거래가 없던 분기는 가장 가까운 거래 분기 값 × 그사이 구 반복매매지수 변화. 대출 비율·금리(단순 이자)는 선택. 산 때·판 때의 구 공포탐욕지수와 가격 흐름 아래 공포탐욕 띠. 단지를 2~3개 고르면 같은 기간을 나란히 비교해요(산 때 = 0% 선 그래프 + 서울 전체 점선, 색은 색맹 구분 검사를 통과한 주황·청록·보라). 주소(#단지:평형,단지:평형)로 비교를 공유할 수 있어요. 세금·수수료 제외, 매매 신호 아님. 기록은 그 브라우저(localStorage)에만.
- 신고가·모의 투자 결과(`results_highs/`, `results_sim/`)는 저장소에 올리지 않고 월간 갱신·배포 때 다시 계산해요.

## 수도권·광역시 확장 (2026-10-20~)
서울 엔진(시작할 때 v3.3, 지금 v3.5)을 경기·인천·부산·대구·광주·대전·울산에 옮겨, 미리 정한 기준을 넘는 지역만 공개해요. 2026-10-22에 지역 엔진을 고정했고 7곳 모두 기준을 넘었어요.

**자료가 있는지** (모두 확인)

- **공공데이터만 쓰는 버전** (2026-10-21, 그때 엔진 v3.3·기준월부터 잰 값, `public_clean.py`·`public_keys.py`·`public_p7.py`·`public_validate.py`·`public_own.py`·`public_own_region.py`): 같은 방식으로 잰 KB판 서울 0.59(5년 구간 중앙값 0.45)에 비해, 상업 이용 근거가 있는 공개 자료만 쓴 판(P5, 주가·구글 검색량도 뺌)은 0.40(0.21), 국토연 주택매매 소비심리(KOSIS)·주택금융공사 K-HAI(HOUSTAT)를 더한 판(P6)은 0.43(0.24), PIR을 K-HAI로 바꾼 마지막 판(P7)은 0.48(0.28)이었어요. P7은 서울 공개 기준을 겨우 넘었지만 KB판과의 차이가 90% 구간 0.03~0.21로 KB판이 분명히 나았고, 지역은 대전·울산·인천만 기준을 넘었어요(광주·대구 미달). 점수 자체는 KB판과 상관 0.89, 다섯 구간 중 한 칸 안에서 99% 일치했어요. 가장 큰 차이는 KB 중개사 설문(매수우위, 0.57)을 대신할 공공 자료가 약하다는 점이에요(부동산원 매매수급 0.25). KOSIS·HOUSTAT 원자료는 저장소에 올리지 않아요(`kosis_fetch.py`·`houstat_fetch.py`로 받음, 키는 `.env`).
- **구 전용 엔진**: 구 고유 지표만 쓰면 시간 정확도가 0.40으로 떨어져요. 상대 엔진은 평균은 높았지만 해마다 들쭉날쭉했어요.

## 처음 한 번 설정
1. **Settings → Secrets and variables → Actions**에 저장소 비밀값 세 개를 추가해요.
   - `DATA_GO_KR_KEY`: 공공데이터포털 인증키 (Encoding 키)
   - `REB_KEY`: 한국부동산원 R-ONE 인증키
   - `ECOS_KEY`: 한국은행 ECOS 인증키
   - 공공데이터포털에서는 실거래가 API와 함께 **'국토교통부_건축HUB_건축물대장정보 서비스'** 활용신청이 필요해요(같은 키).
   - 브이월드 키(`VWORLD_KEY`, 오래된 단지 토지 면적)는 로컬 `.env`에만 둬요. 한 번 채워 저장소에 올렸으니 자동 갱신에는 필요 없어요.
2. **Settings → Pages → Build and deployment → Source**를 `GitHub Actions`로 바꿔요.
3. **Actions → 월간 자동 갱신 → Run workflow**로 한 번 실행해 봐요. 실행 목록 화면의 Run workflow를 눌러야 최신 코드로 돌아요. 예전 실행 안의 Re-run은 그때 코드로 돌아요.

## 로컬에서 돌리기
```
python -m venv .venv && .venv/bin/pip install -r requirements.txt
# .env 에 DATA_GO_KR_KEY=..., REB_KEY=..., ECOS_KEY=... 를 넣고 (저장소에 올리지 않음)
./update.sh --no-publish        # 자료 받기 + 재계산
./update.sh --skip-fetch        # 받은 자료로 재계산만
.venv/bin/python bldg_fetch.py fill   # 건축물대장: 못 찾은 단지를 이름으로 다시 찾기
.venv/bin/python bldg_fetch.py land   # 건축물대장: 오래된 단지 대지면적·용적률 (VWORLD_KEY 필요)
.venv/bin/python bldg_fetch.py --regions        # 수도권·광역시 단지 건축물대장 (fill·land도 --regions 가능)
.venv/bin/python apt_score.py busan              # 단지 점수를 한 지역만 (highs_build.py·sim_build.py도 같음, 인자 없으면 서울+모든 지역)
.venv/bin/python og_build.py          # 링크 미리보기 그림 다시 만들기 (Chrome 필요)
```

## 자료 출처와 이용 조건
- 계산에 쓰는 자료: KB부동산 데이터허브, 한국부동산원 R-ONE(대구 공급 보정의 국토부 주택착공실적 포함), 국토교통부 실거래가(공공데이터포털), 청약홈, 한국은행 ECOS, 네이버 금융, 구글 트렌드.
- 공공판 시험에만 쓴 자료: KOSIS(국토연구원 주택시장 소비심리지수), 한국주택금융공사 HOUSTAT(주택구입부담지수 K-HAI).
- 단지 정보: 국토교통부 건축물대장(건축HUB), 국토교통부 토지대장 면적(브이월드 토지임야목록).
- 사진: 위키미디어 공용의 CC0·퍼블릭 도메인 사진 (출처는 바닥글과 `assets/img/credits.json`).
- 각 원자료의 저작권과 이용 조건은 해당 기관에 있어요.
- 이 저장소에는 공공데이터(국토부 실거래·건축물대장, 한국부동산원, 청약홈, 한국은행)와 계산 결과만 올려요. KB부동산·네이버 금융 원자료와 그 원값이 담긴 지표 표는 올리지 않아요.
- 공개 사이트와 보고서에는 직접 계산한 점수와 실거래 반복매매지수만 실어요.
- 지수 성능의 상당 부분이 KB 자료(중개사 설문, 가격지수, PIR·구매력)에서 나와요. 상업적으로 쓰려면 KB 자료 이용 조건을 먼저 확인해야 해요.
