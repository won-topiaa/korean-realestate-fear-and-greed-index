# 서울 아파트 공포탐욕지수

주식시장의 공포탐욕지수(CNN Fear & Greed Index)를 서울 아파트 시장에 옮긴 지수예요. 시장 심리를 0~100으로 나타내고(0 극단적 공포, 50 중립, 100 극단적 탐욕), 서울 전체·5대 권역·25개 구로 나눠 볼 수 있어요.

- **공개 사이트 (지도)**: https://won-topiaa.github.io/korean-realestate-fear-and-greed-index/
- **백테스트 보고서**: https://won-topiaa.github.io/korean-realestate-fear-and-greed-index/report/
- **단지 검색 (최근 실거래 위치)**: https://won-topiaa.github.io/korean-realestate-fear-and-greed-index/apt/
- **갱신**: 매달 20일 09:17(한국 시간) GitHub Actions가 자료를 새로 받아 다시 계산하고 배포해요.
- 계산 규칙과 갱신 절차: [README_자동갱신.md](README_자동갱신.md)

### 단지 검색: 최근 실거래 위치 점수 (2026년 10월 추가)
단지 이름이나 동(초성도 가능)으로 찾으면, 그 단지 평형별로 **가장 최근 실거래가가 최근 거래들 사이에서 어디쯤인지** 0~100으로 보여줘요. 주식 스토캐스틱(%K)과 같은 식이에요.

- **점수** = (최근 거래 보정가 − 비교 거래 최저) ÷ (최고 − 최저) × 100
- **비교 거래**: 같은 단지·같은 평형의 최근 10건(2년 안). 같은 평형이 5건 미만이면 같은 단지 다른 평형 거래를 환산해 10건까지 채워요. 5건이 안 되면 점수를 내지 않아요.
- **보정가**: 층(8~10층 기준), 그사이 구 시세 변화(구별 실거래 반복매매지수), 평형 차이를 맞춘 가격. 해제·직거래는 빼요.
- **설계 근거** (`apt_study.py`, 2006~2026 실거래 141만 건):

| 항목 | 결과 |
|---|---|
| 기간 | 1개월은 같은 평형 5건 이상인 단지가 0.2%뿐. 고정 기간 대신 '최근 10건(최대 2년)'이 범위와 정확도 모두 좋았음 |
| 층 보정 | 1층 −9.0%, 2층 −5.3%, 3층 −3.4%, 4층 −2.5%, 5층 −1.7%, 6~7층 −0.7%, 8~10층 기준, 11~29층 +0.3~0.8%, 30층 이상 +3.1% (2006~15년과 2016~26년이 거의 같음). 넣으니 같은 평형 다음 거래와의 순위상관이 0.41 → 0.50 |
| 평형 환산 | 단지별 평형 비율(최근 3년)로 환산하면 2021년~ 거래 가격 오차 중앙값 4.6% (㎡당 같은 값 14.3%, 서울 공통 비율 8.8%, 같은 평형끼리 3.3%) |
| 다른 평형으로 채우기 | 같은 평형 5건 미만일 때만 채우면 정확도는 그대로(0.48)이고, 지금 점수가 나오는 단지·평형이 73% → 88%. 평형을 무조건 섞으면 오히려 나빠짐(0.44) |
| 의미 | 2014~2026년 82만 건: 80점 이상 뒤 같은 평형 거래는 평균 2.0% 낮았고, 20점 이하 뒤에는 4.6% 높았음(시장 변화를 뺀 값) |

- 지금(2026-10-14 신고분): 9,271개 단지, 최근 2년 거래가 있는 평형 14,896개 중 10,641개에 점수.
- **출렁임 (이 브랜치 `apt-volatility`에서만)**: 비교 거래를 시간순으로 놓고 이웃한 두 거래 보정가의 차이(%)를 평균한 값(주식 ATR과 같은 생각). 서울 단지·평형 중간값 ±4.8%(4분의 1 지점 ±3.5%, 4분의 3 지점 ±6.6%). 화면에 '출렁임 ±2.7% · 작은 편'처럼 보여줘요. 메인에 합칠지는 아직 정하지 않았어요.
- 세대수·동수·용적률·건폐율은 건축물대장(건축HUB) 연결을 준비해 뒀어요(`bldg_fetch.py`). 공공데이터포털에서 **'국토교통부_건축HUB_건축물대장정보 서비스' 활용신청**을 하면 월간 갱신 때 자동으로 채워져요(처음엔 9천여 단지라 몇 번에 나눠 받아요).
- 단지 자료(`results_apt/`)는 저장소에 올리지 않고 배포 때마다 저장소의 실거래 자료로 다시 계산해요(1분 안쪽).

| `monthly-update.yml` (월간 자동 갱신) | 매달 20일 00:17 UTC, 수동 실행 가능 | 원자료 받기 → 재계산 → 점검 → 결과 커밋 → Pages 배포 |
| `site-deploy.yml` (화면만 다시 배포) | `map/template.html`, `report/template.html`, `apt/template.html` 등을 고쳐 올릴 때 | 저장소의 최신 결과로 사이트만 1~2분 안에 다시 배포 (단지 검색 자료는 여기서 다시 계산) |
| `cache-keepalive.yml` (원자료 캐시 유지) | 4일마다 | KB·네이버 원자료 캐시를 꺼내 써서 GitHub의 7일 만료를 막음 |

원자료 하나가 실패하면 지난 자료로 계속 진행해요(파일은 다 받은 뒤에만 바꿔 쓰고, 자료처마다 시간 한도가 있어요). 계산이나 점검이 실패하면 커밋·배포하지 않아요. KB·네이버 원자료는 저장소에 올리지 않고 Actions 캐시에만 보관해요.

---

## 처음 한 번 설정
1. **Settings → Secrets and variables → Actions**에 저장소 비밀값 세 개를 추가해요.
   - `DATA_GO_KR_KEY`: 공공데이터포털 인증키 (Encoding 키)
   - `REB_KEY`: 한국부동산원 R-ONE 인증키
   - `ECOS_KEY`: 한국은행 ECOS 인증키
2. **Settings → Pages → Build and deployment → Source**를 `GitHub Actions`로 바꿔요.
3. **Actions → 월간 자동 갱신 → Run workflow**로 한 번 실행해 봐요. 실행 목록 화면의 Run workflow를 눌러야 최신 코드로 돌아요. 예전 실행 안의 Re-run은 그때 코드로 돌아요.

## 로컬에서 돌리기
```
python -m venv .venv && .venv/bin/pip install -r requirements.txt
# .env 에 DATA_GO_KR_KEY=..., REB_KEY=..., ECOS_KEY=... 를 넣고 (저장소에 올리지 않음)
./update.sh --no-publish        # 자료 받기 + 재계산
./update.sh --skip-fetch        # 받은 자료로 재계산만
```

## 자료 출처와 이용 조건
- 계산에 쓰는 자료: KB부동산 데이터허브, 한국부동산원 R-ONE, 국토교통부 실거래가(공공데이터포털), 청약홈, 한국은행 ECOS, 네이버 금융, 구글 트렌드.
- 각 원자료의 저작권과 이용 조건은 해당 기관에 있어요.
- 이 저장소에는 공공데이터(국토부 실거래·건축물대장, 한국부동산원, 청약홈, 한국은행)와 계산 결과만 올려요. KB부동산·네이버 금융 원자료와 그 원값이 담긴 지표 표는 올리지 않아요.
- 공개 사이트와 보고서에는 직접 계산한 점수와 실거래 반복매매지수만 실어요.
- 지수 성능의 상당 부분이 KB 자료(중개사 설문, 가격지수, PIR·구매력)에서 나와요. 상업적으로 쓰려면 KB 자료 이용 조건을 먼저 확인해야 해요.
