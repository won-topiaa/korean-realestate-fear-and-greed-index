# 서울 공포탐욕지수 v3.3 — 월간 자동 갱신

## 언제, 무엇이 도나
매달 20일 09:17(한국 시간) GitHub Actions(`.github/workflows/monthly-update.yml`)가 실행한다. Actions 탭에서 수동 실행도 된다.

GitHub 예약 실행은 몇 시간 늦거나 빠지기도 해서(2026-10-20 본 실행이 빠짐) 예비 시각을 둔다: 20일 15:43·21:43, 21일 09:43, 22일 09:43.
예약 실행은 먼저 `automation/monthly_due.sh`로 확인해 이번 달 갱신이 이미 됐거나(main의 `update_summary.json` 실행 시각이 20일 이후) 먼저 시작한 갱신이 돌고 있으면 바로 끝낸다.
그래서 앞 실행이 실패하면 다음 예비 실행이 다시 시도한다. 수동 실행은 확인 없이 바로 갱신한다.
그래도 안 되면 `cache-keepalive.yml`(4일마다, 21·25·29일)이 감시로 월간 갱신을 다시 실행하고 '월간 자동 갱신 확인 필요 (YYYY-MM)' 이슈를 열어 알린다.

1. **원자료 갱신**: KB부동산, 한국은행 ECOS, 네이버 금융, 구글 트렌드, 한국부동산원 R-ONE, 국토부 실거래(최근 5개월 재수집), 청약홈
2. **재계산** (v3.3): 실거래 반복매매지수 → 지표 → 서울 → 5대 권역·25개 구 → 실시간 기록 → 지도·보고서·사이트
3. **점검**: 최신 점수가 0~100 안인지, 기준월이 바뀌었는지, 지난번보다 20점 넘게 튄 곳이 있는지, 최신 달에 빠진 표가 있는지
4. **반영**: 갱신된 자료를 저장소에 커밋하고 `site/`를 GitHub Pages에 배포한다

화면(`map/template.html`, `report/template.html`)만 고쳐서 올리면 `.github/workflows/site-deploy.yml`이 자료 갱신 없이 사이트만 1~2분 안에 다시 배포한다.

원자료 하나가 실패하면 지난달 자료로 계속 진행한다. 원자료 파일은 다 받은 뒤에만 바꿔 쓰고(중간에 끊기면 지난 파일 유지),
부동산원은 응답 코드와 전체 건수를 확인해 덜 받은 자료를 저장하지 않는다. 자료처마다 시간 한도(`update_pipeline.FETCH_BUDGET`, 합계 2시간)가 있어
한 곳 서버가 멈춰도 전체 실행이 150분을 넘기지 않는다. KB·네이버 원자료 캐시는 `cache-keepalive.yml`이 4일마다 꺼내 써서 7일 만료를 막는다.
월간 갱신과 '화면만 다시 배포'는 같은 묶음(`pages`)이라 겹치지 않고 차례로 돌며, 갱신 중 다른 커밋이 들어오면 그 위에 얹고 화면을 다시 빌드한다. 재계산이나 점검이 실패하면 커밋·배포하지 않는다.
로컬 맥에서 돌릴 때는 점검 뒤 헤드리스 Claude가 예전 Claude 아티팩트(지도·보고서)도 덮어쓸 수 있다 (`./update.sh`, CI에서는 생략).

## 직접 돌리기
```
./update.sh                 # 전체 (갱신 + 게시)
./update.sh --no-publish    # 게시 없이 갱신만
./update.sh --skip-fetch    # 이미 받은 자료로 재계산만
```

## 결과 확인
- 실행 기록: `logs/update_YYYYMMDD_HHMM.log`
- 최신 점수 요약: `results_zone/update_summary.json`
- 달마다 쌓이는 점수: `results_zone/update_history.csv`
- 출처별 성공·실패: `results_zone/update_status.json` (키는 지워서 기록)

## 맥에서 예약 실행 (선택)
GitHub Actions를 쓰면 필요 없다. 맥에서도 돌리고 싶으면 `automation/install.sh`(등록), `automation/uninstall.sh`(해제).
프로젝트가 바탕화면에 있으면 macOS 권한 때문에 예약 실행이 멈출 수 있어, 바탕화면 밖 폴더에서 쓰는 게 안전하다.

## 엔진 정의 (v3.3, 바꾸지 않는 것)
- **표 구성**: 2009년 이전부터 자료가 있는 지표 34개를 같은 원자료끼리 묶은 25표 (`v3.py`의 MERGE·DROP·GOOGLE). 구글 검색어 6개는 한 표.
- **묶기**: 표를 선행·동행·후행 3그룹으로 나눠 같은 비중으로 평균. 각 지표는 과거 120개월 백분위. 검색량이 너무 적던 시기(직전 2년 평균 5 미만)의 검색 지표는 제외.
- **눈금**: 점수 = 50 + 1.5 × (원점수 − 50), 0~100.
- **보고서 비교 기준 '실거래 6개월 변화'**는 그달에 알 수 있던 거래만으로 다시 추정한 값(`rs_vintage.py` → `data/repeat_sales_rt.csv`, 매달 한 달씩 덧붙임).
- **시점** (`timing.py`): 20일 갱신 때 아직 공개 전인 지표(부동산원 거래 통계·미분양, 월평균 금리, 월말 주가, 검색량, 청약)는 1개월, 실거래·미분양·주담대 금리는 2개월, PIR·구매력은 3개월 늦춤. 가계신용(분기)은 분기 끝 3개월 뒤부터 쓰고 다음 발표까지 이어 씀.
- **v3.3** (2026-10-14): 실거래 신고가·급락은 모든 거래로(해제·직거래 표시가 2020~2021년에 생겨 전후 정의가 달랐음), 급락은 직전 다른 날 거래와 비교, 미분양 2개월 늦춤, 권역·구는 지역 자료가 시작되기 전까지 상위 지역 값. 서울 성적은 같음(5년 중앙값 0.448). 점수화 기간 10년은 7·15년·누적과 미리 정한 기준으로 비교해 유지.
- **v3.2** (2026-10-14): 금리·가계신용을 FRED·BIS·KB 표 대신 한국은행 ECOS 원자료로. 주택가격전망 CSI(전국)는 보조 지표. 5년 중앙값 0.44 → 0.45, 최저 −0.20 → −0.16.
- **권역·구**: 가격·전세·거래량·매입자 구성·실거래 지표는 그 권역(구) 값, 금리·검색량·주가·PIR 등은 서울 값. 구 지수에서 부동산원 수급·미분양·상승 구 비율은 권역 값, KB 설문은 강북·강남 값 (`zone_index.py`). 2011년 이후 25개 구 평균 정확도는 구 지수·권역 지수·서울 지수가 거의 같다(0.55).
- **공식 기록**: 2011년 2월부터 (그 이전은 지표 구성이 불완전해 참고용).
- 빅카인즈 뉴스는 점수에 쓰지 않는다 (백테스트에서 개선 없음, 약관상 자동 수집 불가). KB 분양·입주 일정은 실시간 계산이 안 돼서 쓰지 않는다.

## 서울 안 상대 강도 (구)
공포탐욕 점수와 별개로, 구마다 신고가 비중(최근 3년 최고가보다 비싸게 팔린 거래 비율, 3개월 평균, 2개월 늦춤)의 25개 구 안 순위를 보여준다.
근거는 `gu_engine_study.py`: 2011년 이후 구 점수 순위로 구끼리 이후 1년 상승률 순위를 맞힌 정도는 0.09로 약했고, 신고가 비중 순위는 0.24(15년 중 13년 양수)였다.
12개 지표를 본 뒤 고른 것이라 실시간 기록에 `구상대강도-v1`로 따로 쌓아 검증한다(달마다 구끼리 순위로 채점).

## 실시간 검증 기록
`results_zone/live_log.csv`에 매달 발표한 점수를 그때 값 그대로 쌓는다. 점검을 통과한 GitHub Actions 실행에서만 기록하고(로컬은 `--record`를 줄 때만), 엔진 버전은 지도 자료를 만든 버전으로 적는다. 지우거나 고치지 않는다.
12개월 뒤 실거래 가격이 나오면 `live_track.py`가 이 기록만으로 성적을 매긴다 (첫 결과는 2028년 하반기 예상).
엔진을 바꾸면 버전 이름(`v3.VERSION`)을 올려서 기록을 구분한다.

## 키
`.env`에 공공데이터포털(`DATA_GO_KR_KEY`), 한국부동산원(`REB_KEY`), 한국은행 ECOS(`ECOS_KEY`) 키가 있다. GitHub Actions는 같은 이름의 저장소 Secret에서 읽는다. 키가 만료되면 이 파일만 바꾸면 된다.
